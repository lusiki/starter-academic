The predictions scoreboard

Every forecast claim, dated, measurable, gradeable — and checked by a script that can fail

Supplement
Author

Luka Šikić

Published

July 28, 2026

This is the scoreboard, and it is the only page that changes after the freeze. The forecast prose is fixed; the retrospective charts keep extending themselves as the corpus grows; this table gains a resolution — a date, a verdict, an evidence link — as each claim comes due.

Every prediction obeys the same rules. It is dated. It is binary or numerically measurable. It carries a probability in steps of 0.05. It names how it will be scored. It must not already be true. It must say what does not count. Since 2026-07-28 it must also name its nearest miss — the closest case observed and exactly what that case lacks — and the countervailing mechanism that would make it fail for the wrong reason. Those two additions exist because a register of institutional claims otherwise spends years reporting the same uninformative word: open.

Those rules are not new. What is new is that a script now enforces them and the build fails if one is broken. That change is the whole of this page’s second draft, and it is worth explaining why it was needed, because the failure was instructive.

The rules were stated and nothing enforced them

The first version of this page announced five rules and checked them once, by hand, on the day it was written. An outside fact-check some months later found fifteen defects. Not one was a bad guess about the world. Every single one was a rule that had been written down and then left to memory:

What went wrong Where it showed up
A baseline was typed into a spreadsheet cell that no script ever recomputed Three claims carried numbers the database had already contradicted
The must not already be true rule was applied once, by hand Two more claims were already true when written, on top of the four caught at drafting
A claim named a resolution set that had never been written down Two claims could not have been scored at all, in 2028 or ever
A claim never said which near-miss counted Two claims had a real-world candidate that either satisfied them or did not, with no way to tell
The page hand-typed which claims the database scores It named three; the data said four, and only one of the three was right
The page said at tag v1.0 nine times The repository had no tags. Nothing was frozen

The underlying error is one thing wearing six hats. This project’s first working rule is that every number is measured, never asserted — the corpus recomputes its own claims and reports drift when prose and database disagree. The forecast layer was the one place exempted from that discipline, and it is the one place that rotted.

So the rules became gates.

Eight gates, run before this page renders

scenario/R/score_predictions.R runs on the committed data — no database needed — and exits non-zero if any claim fails. It is wired into CI, so a stale baseline breaks the build rather than quietly shipping.

Gate What it refuses to let through
G0 schema A malformed claim: bad horizon, a probability off the 0.05 grid, or a database-scored claim with nothing measurable behind it.
G1 baseline A stated number that no longer recomputes from the data. Each baseline names its metrics; the gate recalculates them and reports DRIFT.
G2 falsity A claim shipped without a dated check that it is not already true, with evidence substantial enough to re-examine.
G3 artifact A claim that does not name a frozen file, or names one whose hash has changed since the freeze.
G4 excludes A claim that never says what does not count.
G5 references A page pointing at a claim id that does not exist — a dangling pointer to something retired.
G6 freeze A scoring input edited after the freeze. Every pinned file is re-hashed on every run.
G7 nearest A claim that reports ‘not found’ without naming its closest observed case and exactly what that case lacks.
G8 counter A claim that never says how it could fail for the wrong reason — because the channel it counts through closed, not because the thing failed to happen.

The gates are themselves tested adversarially — tests/testthat/test-prediction-gates.R breaks each one on purpose against a throwaway copy of the tree and asserts the build goes red. A gate that has never been observed to fail is not a gate, it is a decoration.

The freeze is a file, not a phrase

The previous draft promised that definitions were fixed “at the tag”. There was no tag. Worse, two claims named a set — the NBER papers “embargoed at v1.0”, the 2026 tool cohort — that nobody had ever written down, so at resolution time there would have been no way to recover which rows the claim had meant. A forecast whose denominator is reconstructed after the fact is not a forecast.

The freeze is now an object: scenario/data/frozen/MANIFEST.md, cut on 2026-07-28 from commit 9eb3c699af5d, pinning 16 files by SHA-256. It pins three kinds of thing, because pinning only one is what let the baselines rot:

  • the cohort a claim resolves over — the 47 NBER papers are now a file with two empty columns waiting to be filled in as mirrors are found;
  • the definition its measurement uses — the vendor patterns P15 promises to be rescored on, and the manuscript/results vocabulary P14 turns on, are frozen data read by the measurement code rather than editable constants inside it;
  • the toolchain that computed the baseline, which is this corpus’s own hard-won lesson: a library upgrade once changed document text extracted from byte-identical bytes, and nothing could see it.

Cutting a git tag remains a maintainer decision and the page no longer pretends one exists.

The retirement register, and what it keeps catching

Before releasing, every claim was checked against the world rather than against intuition. Six failed for being already true — four at drafting, two at an outside check months later, and one claim failed twice: retired once for describing something NLP groups had already built, then rewritten to ask whether economists would build one, which they had done four months before the rewrite was drafted.

The 2026-07-28 pass added nine more rows, and one of them is the same disease a third time. P9 v2 was at risk of being already true: secondary reporting has Windsurf folded into Devin Desktop in June 2026 and Continue.dev acquired by Cursor, which is two qualifying absorptions inside the window the claim was drafted over. Rather than retire it a second time, its cohort was closed to the products still independent at the freeze and the four absorbed ones were named as exclusions — the same repair P4 and P12 received.

Three further rows record something less dramatic but worth admitting: P1, P8 and P14 were rewritten in place on 2026-07-27 with the reasons living only in their baseline_prose, so a reader could see six retirements and reasonably assume the other nine claims had never changed. They are entered retrospectively, dated as such.

They are recorded rather than deleted, because the retirement is more informative than the prediction would have been. A forecast that is already true is not a cheap win; it makes the forecaster look better calibrated than he is, and it makes every other number on the page less believable.

The pattern is the same every time, and it is worth naming. The forecaster’s error was never direction. It was always the clock. The informal, fast-moving parts of this change had already happened while the formal parts had not: journal disclosure policies, guide publication, a health-economics reporting checklist, replication vocabulary in job ads, an economist-built benchmark. Agent-run reproduction gates, an economics-scoped standard, and independent reuse of that benchmark had not. That is the register asymmetry from the main page showing up inside the forecast itself, and it is why the surviving claims cluster on the slow side of the divide.

One retirement is a different animal and deserves its own note. The claim about coding assistants was not retired for being true — it was retired for being unmeasurable in principle. It asked whether the share of newly released research tools that are standalone coding assistants falls relative to 2026. That share cannot be computed, now or ever: 99 tools sit in the collection and only 19 carry a date at all, because a tool homepage is a living page with no release date and never will have one. The other 80 are marked not_applicable — a category error, not a gap. No freeze could have fixed that, and no amount of care in the wording would have caught it. Only trying to compute the number did.

P3 · rest of 2026 · p = 0.20 (awaiting review)

Not yet true, checked 2026-07-28. Open, over a roster that now exists. The version this replaces named the field’s informal method guides without ever writing down which guides, so one-in-five and one-in-fifty would have scored identically. Ten are now named with their URLs and their DOI status at the freeze; none carries a DOI.

What does not count. A work that was a peer-reviewed journal article from the start does not count. Korinek’s JEL survey carries a DOI and reads like a guide, but a journal article is not an informal guide ACQUIRING an identity. To qualify, the guide must have circulated informally first - on an author site, a public repo, or a course page - and then get a DOI. Self-citation does not count - the citing article must share no author with the guide, because the guide’s own author citing it is a formality rather than the return path this claim is about. An NBER working paper is not a peer-reviewed economics article here. And a DOI minted automatically by a preprint server does not count as ACQUIRING a citable identity: the deposit must be deliberate (Zenodo, JOSS or a journal), or the claim resolves on infrastructure rather than on the field changing its mind.

The roster is closed at the freeze: a guide that first circulates afterwards cannot resolve this claim, because a claim whose population grows is a claim that gets easier with time.

P4 · rest of 2026 · p = 0.40 (awaiting review)

A named, numbered reporting checklist of at least eight items for LLM-based measurement, scoped specifically to economics rather than to a broader field that includes economics, is released as a preprint or peer-reviewed article.

Not yet true, checked 2026-07-27. Open as narrowed. The version this replaces said ‘general economics’ without saying whether an economics-inclusive checklist counted, which made it unscorable rather than merely uncertain: GUIDE-LLM satisfies one reading of that phrase and fails the other. The wording now says which reading applies.

What does not count. Two existing checklists are excluded and neither can satisfy this claim. ELEVATE-GenAI (ISPOR, Value in Health, 2025) is scoped to health economics and outcomes research. GUIDE-LLM (Nature Human Behaviour) is a 14-item peer-reviewed checklist for behavioural and social science, developed with economics experts among others - it is economics-INCLUSIVE, not economics-scoped. A qualifying checklist must name economics as its scope, not as one discipline among several. The eight-item threshold is arbitrary. It is frozen here rather than defended, precisely so that whoever scores this cannot quietly bend it.

How it will be scored (public pages). Three mechanical conditions, fixed here so resolution does not turn on an adjective: (a) eight or more numbered items; (b) the word economics or economic appears in the checklist’s title or its own stated scope; (c) a majority of credited authors hold economics affiliations. Any public version during the window counts, so a preprint that reaches eight items on revision qualifies from that revision onward. The NUMBER of qualifying checklists is recorded, not just the yes/no - two rival checklists confirm the underlying thesis more strongly than one, and the register should be able to say so.

Nearest miss. GUIDE-LLM: 14 numbered items, peer-reviewed, economics experts on the panel - it fails condition (b) alone, being scoped to behavioural and social science. ELEVATE-GenAI fails the same condition from the health-economics side.

How this could fail for the wrong reason. A field can acquire its reporting standard by adopting a neighbour’s rather than writing its own. If economics simply cites GUIDE-LLM, this claim fails while the need it names is met - which is exactly why P11 scores the citation and this one scores the artifact.

Frozen against. scenario/data/predictions.csv

Reference class. A field usually gets its reporting standard from its most regulated corner first. Health economics already has one, and economics has the same trigger without the same regulator.

Cluster. standards

Most probabilities are awaiting review, and the page says so

17 of the 18 claims were materially rewritten in this draft — narrowed to exclude a near-miss, re-baselined against corrected counts, or replaced outright after a retirement. Their probabilities are carried over from the version they replace and are marked awaiting review above, because a number attached to a claim that has since changed is not a forecast, it is a leftover.

Carrying them over visibly is the honest option. Silently keeping them would overstate calibration; silently adjusting them would be revising a forecast after seeing the evidence, which is the thing this page exists not to do. They are the maintainer’s to set, once, before the next freeze.

How this register will be scored, promised in advance

Assigning a probability and never doing the arithmetic is not forecasting, it is decoration. So the commitment is made here, before any claim resolves: every resolution is scored with a Brier score, and the register reports the running mean. A claim that resolves void — P7 and P15 can, if the channel they count through closes or a stated guard is broken — is excluded from the mean and reported separately, because scoring a bet whose measuring instrument broke would be worse than not scoring it.

Eighteen claims is a thin sample for calibration, and the horizons are lumpy: 4 resolve this year and the rest across 2027 and 2028. The number will be noisy for years. Publishing it anyway is the point — an unfalsifiable forecast register is exactly what this page was built to stop being.

Prefer a count to a share, whenever you own the denominator

Two claims on this page had to be rewritten because their truth depended on how the collection happened to be composed rather than on anything about the world.

The first measured the verification share of tools. That share fell — not because the field built fewer referees, but because the tool denominator nearly tripled when an automated watcher swept in general-purpose infrastructure. It now scores on counts and rank, which the composition cannot move.

The second asked for the share of newly released tools in a category, and could not be rescued at all, because the corpus cannot observe release dates for living pages.

The lesson generalises past this page. A share is a claim about two numbers, and if you control one of them you have not made a prediction — you have made a plan.

Forecast freeze manifest

Freeze date: 2026-07-28 Commit: 5a5018def8c7b2a14fe0a703ac02227d9d93a2c6 Git tag at this commit: none — this freeze is not tagged. The manifest below, not a git tag, is what pins it.

This file is what the predictions scoreboard means by frozen. It replaces the phrase “at tag v1.0”, which the page used nine times while the repository had no tags at all and therefore froze nothing.

A prediction is only reproducible if three things are pinned together: the cohort it resolves over, the definition its measurement uses, and the toolchain that computed its baseline. Pinning one alone is what let three published baselines go stale without anyone noticing.

Re-cut with Rscript scenario/R/freeze.R. score_predictions.R verifies every hash below on every run and fails the build on a mismatch, so a scoring input cannot be edited quietly.

Cohorts frozen here

  • nber_embargoed.csv — 47 NBER working papers under embargo at the freeze. P10’s resolution set. It carries title, author and URL so the 2028 search can run without this database, and two empty columns (resolved_on, resolved_mirror_url) for recording each mirror as it is found. Scoring P10 means filling those in, not re-deriving which papers were meant.

What is deliberately NOT frozen

  • scenario/data/derived/*.csv — regenerated from the database by build_metrics.R. They are outputs, and the point of the gates is that a baseline recomputed from them must still match what the prediction claims.
  • The retrospective charts and the corpus itself, which keep growing on purpose. Only the forecast layer freezes.
